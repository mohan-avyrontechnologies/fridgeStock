# Testing

Run everything with `npm run lint && npm run typecheck && npm test && npm run test:e2e` (see the [README](../README.md#running-the-tests)).

**Shared test cases (both languages).** `shared/test-cases/*.json` holds inputs and expected outputs for the shared logic: dates, alerts, barcodes, wording, the catalog, `estimateExpiry` and printed dates, the priority engine, the server's wording and every request schema (`validation.json`). The TypeScript suites (`shared/src/testCases.test.ts`, `server/src/tests/sharedCases.test.ts`) and the Python server's pytest (`server-py/tests/test_shared_cases.py`) run every case, so the two languages can never disagree. Add a case once and both languages check it. `validation.json` is written from the zod schemas (`npm run cases:validation -w shared`); run it again on purpose after changing a schema. The Python server's own commands are in [server-py/README.md](../server-py/README.md) (`npm run test:py`, `npm run lint:py`).

**Python server (pytest).** `server-py/tests` ports each `server/src/tests` file as its phase arrives, and adds tests for what the TypeScript server gets from its packages: HTTP behaviour from Express, helmet, cors, body-parser and express-rate-limit (`test_http.py`, with every expected header and ETag recorded from the Node server), tokens and passwords checked against `jsonwebtoken` and Node's bcrypt (`test_tokens.py`, which runs Node), and indexes and documents recorded from Mongoose (`test_models.py`). Tests are grouped by migration phase: `uv run pytest -m phase1` runs one group, which helps on a PC short of memory. `npm run compare:py` runs one journey on the Node server and on the Python server, each with its own empty database, and fails if any response or stored document differs (ids, times and tokens are numbered in order of appearance). One empty MongoDB serves the whole run (or `TEST_MONGO_URI`), and every collection is emptied before each test that uses it.

The seventeen end-to-end journeys:

1. **The spec journey:** sign up → add chicken (1-day lifespan) and eggs (8-day) → FridgeStock shows only the chicken → mark it used → it has disappeared from both the dashboard and FridgeStock
2. Register → add food → FridgeStock → mark used → History
3. Partial use, then waste the rest
4. Validation messages and the expected-expiry preview
5. Reminders
6. One user can't see another user's food
7. Reminder settings and log out
8. **Phase 1:** bulk add a haul → waste one and **Undo** it → save a favourite, use it up, and re-add it with one tap
9. **Phase 2:** open milk (7 → 4 days) → move chicken to the freezer (270 days) → add milk again and see "You usually set 7 days" on Add Food
10. **Phase 3:** the manifest and icons are served and the service worker runs → Settings shows "Turn on reminders" with permission still unasked → switch to one per item at 18:00 and reload → tapping asks for permission → an iPhone in a browser tab sees the Home Screen hint instead
11. **Phase 4:** add leftovers (3 days, tagged) → no AI buttons with AI off → shopping list warns that chicken is already at home → tick and clear bought items → plan tomorrow's chicken curry and reload

Every page visited is also checked for banned wording, sideways scrolling, and **tap targets under 44 px**. The end-to-end API runs with a freshly generated VAPID key pair, and with the sign-up rate limit off (the journeys create more than 20 accounts; the limit itself is unit-tested).

Test databases live in git-ignored `.test-db-*` folders inside the project, not the system temp folder, and are deleted afterwards. The end-to-end run also starts two local stand-ins, one for Open Food Facts (port 4101) and one for the Anthropic API (port 4102, answering the real SDK with canned JSON), so the AI features, barcode look-ups and Photo Check run end to end with no key and no internet. It uses its own ports (API 4100, web 5174), so it never touches your data.

> **Low disk space on the system drive?** Chrome creates a temporary profile for every Playwright test. If that drive is nearly full, point the temp folder elsewhere for the run. For example, in Git Bash: `TMP="$PWD/.tmp" TEMP="$PWD/.tmp" npm run test:e2e` (`.tmp/` is git-ignored).
